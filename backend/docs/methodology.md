# Метод гармонизации и смысл результата

## 1. Сохраняемые наблюдения

MODIS Terra/Aqua и VIIRS SNPP/NOAA-20/NOAA-21 приводятся к одной схеме времени, координат и метаданных. Время FIRMS — UTC. Исправляется вариант `instrument=SNPP`, встречающийся в пользовательском Suomi-архиве. Для температуры сохраняется канал `MODIS_21_22` либо `VIIRS_I4`; общего «гармонизированного значения температуры» нет.

Невалидные координаты, время, неизвестная платформа, несовместимый instrument и неизвестный D/N исключаются с подсчётом в аудите. Невалидные дополнительные числовые параметры становятся null. Слабые/неизвестные confidence остаются в таблице наблюдений; в аналитике используются MODIS ≥30 и VIIRS nominal/high. Эти правила — аналитический выбор, а не равенство вероятностей обнаружения.

`observations` хранит нормализованные версии точек, `detections` — канонический снимок. Идентичность определяется **точным совпадением platform, timestamp, latitude, longitude**, а не пространственной близостью. При совпадении archive предпочитается NRT, затем RT, URT, unknown; внутри одного класса используется последняя импортированная версия. Сохраняются dataset/member и SHA-256 исходного файла. Оригинальные ZIP нужно сохранять отдельно: неизвестные дополнительные колонки CSV не копируются в схему БД.

Две соседние точки VIIRS не сливаются в одну «исходную точку MODIS».

## 2. Общая мера активности

Используется сферическая цилиндрическая равноплощадная проекция:

```
R = 6371.0088 km; c = cos(30°)
x = R * longitude_radians * c
y = R * sin(latitude_radians) / c
gx = floor(x / 10); gy = floor(y / 10)
```

Одна запись активности — занятая **10 км ячейка × UTC-дата × D/N × спутник**. Повторные точки и разные hotspot types внутри такой комбинации учитываются один раз. Если выбрано `daynight=both`, D и N — два отдельных периода; единица называется `occupied_cell_day_periods`.

Ячейка не является нативным пикселем и не определяет выгоревшую площадь. Сетка уменьшает различия в плотности зарегистрированных пикселей и повторных пролётах, но не устраняет их полностью.

Для карты исходных точек AOI проверяется по координатам точки, включая границу полигона. Для сетки, календаря и обучения AOI проверяется по **центру ячейки**. При узких/малых полигонах эти выборки различаются. Долготы у линии перемены дат не оборачиваются; пересекающие её AOI надо разделять на два запроса.

## 3. Калибровка

Активные ячейко-дни агрегируются по 100 км регионам, месяцам, спутникам и D/N. Reference по умолчанию SNPP, но это не наземная истина.

Для каждого source/DN оценивается коэффициент без свободного члена:

```
y = зарегистрированная активность reference
x = зарегистрированная активность source
slope = sum(x * y) / sum(x * x)
prediction = slope * x
```

Для неотрицательных счётчиков slope неотрицателен. Параметры конфигурации неизменны внутри сохранённой модели.

Обучение по умолчанию 2013–2024; тест — 2025. Для NOAA-20 обучение начинается позже в соответствии с фактическим пересечением, для NOAA-21 доступны только два календарных года обучения. Рассматриваются полные месяцы внутри пересечения первых/последних дат архивных наблюдений. Эти даты — границы файлов, не подтверждение непрерывного наблюдения.

Регионы выбираются **только по train**, отдельно для D/N: у обоих спутников должна быть хотя бы одна запись в регионе. Внутри них таблица пар — объединение положительных source/reference регион-месяцев. Отсутствующая запись становится нулём зарегистрированной активности; месяцы без записей у обоих не создаются. Поэтому метрики условны относительно такого support и не являются оценкой обнаружения всех пожаров/отсутствия пожаров.

Bootstrap повторно выбирает целые годы обучения с возвращением (200 повторов, seed=42). Интервал 2.5–97.5% показывает вариабельность slope. Он не является интервалом прогноза, не оценивает все источники неопределённости и особенно слаб при двух годах обучения.

На test рассчитываются MAE, RMSE, суммарное относительное смещение до/после. Пороги предупреждений заданы заранее: отсутствующий/малый holdout, не улучшившийся RMSE, ухудшившийся MAE, |bias|>30%, менее трёх лет обучения. Модель не перенастраивается по результатам 2025 года. Статус улучшения не означает научной валидации на всех территориях.

В отличие от предыдущего ноутбука, поддержка source/reference выбирается отдельно по D/N, точные дубликаты устраняются до аналитики. Небольшие расхождения метрик с ноутбуком ожидаемы и отражены в текущем отчёте.

## 4. Единый календарь

В месяце выбирается **один** источник. Приоритет: reference, NOAA20, NOAA21, Aqua, Terra, SNPP, с удалением повторов. Источник допустим только если его файловый временной диапазон покрывает весь запрошенный фрагмент месяца. Для данных до VIIRS обычно получается Aqua, а до Aqua — Terra.

Выбор не зависит от наличия пожаров внутри AOI: ноль SNPP в конкретном регионе не вызывает подстановку MODIS. Если ни один источник не покрывает месяц, индекс null.

Для всех используемых в запросе калибруемых источников берётся пересечение обучающих регионов отдельно по D/N. Этот support фиксируется на весь запрошенный временной ряд и применяется также к reference. Данные вне него показываются в `excluded_cell_days`; они не исчезают из исходных слоёв. При отсутствии пространственной поддержки индекс null.

`raw_by_platform` — занятые ячейко-дни, `detection_counts_by_platform` — пиксельные детекции. `harmonized_index` — активность выбранного спутника на общем support, умноженная на его коэффициент. Платформы не суммируются. Индекс может быть дробным.

Для source до его первого обучающего месяца или после тестового года требуется `allow_extrapolation=true`. Это явная экспериментальная экстраполяция. Reference в собственных годах не нуждается в межсенсорном коэффициенте. NRT выдаётся отдельно; архивную модель к нему применить нельзя.

Общий support может зависеть от спутников, необходимых для запрошенного периода. Поэтому для сравнения нескольких лет используйте один запрос на весь период; нельзя предполагать, что отдельные запросы с разными временными окнами имеют идентичный support. Seasonality формирует общий ряд baseline+target одной операцией.

## 5. Сезонность и аномалии

Baseline должен закончиться до начала первого target-года. Для каждого календарного месяца вычисляются среднее, стандартное отклонение (ddof=1), медиана и P95 по годам; нужны минимум три значения. Сравниваются полные месяцы. `z=(value-mean)/std`; |z|≥2 — описательный признак необычного периода, не статистический тест с контролем множественных сравнений.

При нулевой дисперсии z=null. Для частичного месяца аномалия не рассчитывается. Нули означают отсутствие записей; проблемы наблюдаемости способны создавать ложные «низкие» периоды. `historically_active_months` — до трёх месяцев с наибольшей положительной средней зарегистрированной активностью, не прогноз пожаров.

## 6. Сопоставление наблюдений

Сферический KD-tree ищет пары центроидов по расстоянию и точной разнице UTC-времени. По умолчанию радиус 1 км, время ±30 минут. Переход через полночь обрабатывается корректно, если обе даты входят в запрос. Результат many-to-many, включая несколько VIIRS-кандидатов около MODIS и неоднозначность.

Это кандидаты совместного наблюдения, не подтверждённые отдельные пожары. Радиус не заменяет геометрию реального пикселя: scan/track сохраняются, но ориентированные footprint-пересечения без дополнительных данных не восстанавливаются. FRP разных пролётов и совпадающих VIIRS-кандидатов не суммируется. Для grid API доступен только максимальный FRP внутри выборки.

## 6a. Слияние в события

Сопоставление пар отвечает на вопрос «увидели ли два сенсора одно и то же в одном пролёте». Слияние отвечает на другой: сколько отдельных очагов стоит за тысячами пикселей и какие из них видели оба семейства сенсоров.

Точки всех выбранных спутников связываются, если расстояние между центрами пикселей не больше `distance_km` (по умолчанию 1,5 км) **и** разница времени не больше `gap_hours` (36 ч). Событие — связная компонента такого графа (single linkage). Для события сообщаются число пикселей по спутникам, первое и последнее наблюдение, число дат, максимальный FRP отдельно по MODIS и VIIRS и класс согласия: `both`, `modis_only`, `viirs_only`.

Событие — кластер пикселей, а не подтверждённый отдельный пожар. Single linkage может склеить соседние очаги в цепочку; уменьшение порогов их разделяет. Класс `viirs_only` ожидаем: пиксель 375 м обнаруживает небольшие и менее горячие очаги, недоступные пикселю 1 км. Различия возникают также из-за времени пролёта, облачности и границ полосы съёмки; масок наблюдения в данных нет. FRP не суммируется ни по пикселям, ни по пролётам, ни по сенсорам.

## 7. Что остаётся научно нерешённым

Для полноценной переносимой гармонизации нужны valid-observation/cloud masks, геометрия Level-2 swaths, контроль времени пролёта, независимые пространственные holdout, устойчивость по сезонам/биомам/годам и чувствительность к размеру сетки и порогам confidence. Нынешний API реализует прозрачный baseline и показывает его неудачные случаи.

`type=0` — presumed vegetation fire, включая сельскохозяйственные палы, а не доказанный wildfire. `all` сохраняет также индустриальные/вулканические и неразмеченные тепловые аномалии. `vegetation` выбирает только type=0; неизвестные type исключаются, и это может сделать NRT-выборку пустой. Модель с другим hotspot_scope применять нельзя.

Исходные данные обозначены как China, но административный полигон страны не предоставлен и не подставлялся. Есть координаты южнее материковой части. Все результаты относятся к загруженному набору и его области покрытия.
